Works with ESLint and oxlint

Turn on strict lint rules today. Fix the old code later.

Record the violations that already exist in approvals.json, per rule and per file. Anything new fails the build. Lower the counts as you clean up.

Get started Try the playground 
{{shell:npm install --save-dev eslint-plugin-exceptions
npx eslint-exceptions             # writes approvals.json}}
{{shell:npm install --save-dev oxlint eslint-plugin-exceptions
npx eslint-exceptions --linter oxlint             # writes approvals.json
npx eslint-exceptions check --linter oxlint       # use in CI}}
How it works

A ratchet for lint debt

Existing violations are approved per file. The count can only go down, so the codebase gets stricter with every change.

1

Record what exists

The CLI runs your linter and writes the current count of every rule in every file.

{{shell:npx eslint-exceptions}}
2

Block anything new

Approved violations are hidden. A file that goes over its count fails, in CI and in the editor.

{{shell:npx eslint .              # ESLint
npx eslint-exceptions check  # oxlint}}
3

Lower the counts

When a file gets cleaner, its count drops. --strict makes sure the file is updated.

{{shell:npx eslint-exceptions check --strict}}
Example

Three approved, one new

src/utils.ts is approved for three no-underscore-dangle violations. Someone adds a fourth.

approvals.json
{{json:{
  "no-underscore-dangle": {
    "src/utils.ts": 3
  },
  "@typescript-eslint/no-explicit-any": {
    "src/api/client.ts": 10
  }
}}}
npx eslint .
src/utils.ts
  9:7  error  Unexpected dangling '_' in '_privateVar4'
       (4 violations found, but only 3 approved
        in approvals.json)  no-underscore-dangle

✖ 1 problem (1 error, 0 warnings)

The three old violations stay quiet. Only the new one is reported, with context. Try it in the playground →

Features

Fits into the tools you already use

{{icon:plug}}

ESLint processor

One line in your flat or legacy config. Works with any parser and plugin.

{{icon:bolt}}

oxlint support

A CLI wraps oxlint's JSON output and applies the same approvals.json.

{{icon:editor}}

Editor integration

The editor hides approved violations, with the ESLint extension or the oxc extension.

{{icon:folders}}

Monorepo friendly

Each package can have its own approvals.json. The nearest one wins.

{{icon:shield}}

Strict mode for CI

Fail when a count is higher than needed, so fixed violations can't come back.

{{icon:swap}}

One file for both linters

oxlint rule codes map to ESLint rule IDs, which helps while migrating.
